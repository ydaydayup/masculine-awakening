# 博主内容问答知识库（多博主）

## 这个库是什么

**一个知识库，里面是 1 位博主。** 检索方式是语义向量：
每个人的视频总结在打包时已向量化，运行时只把用户的问题编码一次，
跟全库向量做余弦比对，取高分。

用户有两种问法，处理方式不同，**第一步必须先分清是哪一种**：

| 问法 | 例子 | 检索命令 |
|---|---|---|
| 点名某位博主 | 「潇洒哥怎么看待彩礼」 | 加 `--blogger` |
| 跨博主 / 不点名 | 「关于彩礼大家怎么看」 | 不加 `--blogger` |

## 数据文件

| 文件 | 管什么 |
|---|---|
| `data/bloggers.json` | 博主清单：名字、别名、条数、各自的相似度阈值。**按名字定位博主就靠它** |
| `data/vectors.npy` + `.json` | 全库向量矩阵（float16，N×512），`blogger_ids` 与 `ids` 逐行平行 |
| `data/summaries.json` | 每条视频的总结，带 `blogger_id` / `blogger` 字段 |
| `data/transcripts.jsonl` | 完整口播稿，同样带 `blogger_id` / `blogger` |

## 收录范围

| 博主 | 别名 | 条数 | 字数 | 时间跨度 |
|---|---|---|---|---|
| 潇洒哥涂龙 | 潇洒哥、涂龙、屠龙、拉闸哥、拉哥、扎哥 | 1273 条 | 1088480 字 | 2024-12-13 ~ 2026-11-26 |

合计 **1 位博主 / 1273 条视频 / 1088480 字口播稿**，时间跨度 2024-12-13 ~ 2026-11-26。

范围以 `config.json` 的 `kb` 字段为准。超出范围一律拒答，不要用常识补。

## 第一步：判断问的是谁

**用户点了名** —— 提到博主名字、别名、ID，或说「这个人」「他」且上下文明确指向一位：

```bash
python scripts/retrieve.py "<用户原话>" --sem --list 5 --blogger 潇洒哥
```

`--blogger` 认三种写法：名字（潇洒哥涂龙）、别名（涂龙/屠龙/拉闸哥）、id 前缀（f73ebd74）。
点名之后**只在这位博主的视频里搜**，答不出来就说这位博主没讲过，**不要拿别人的观点顶上**。

**用户没点名**，或说「这些博主」「大家」「都怎么看」「对比一下」：

```bash
python scripts/retrieve.py "<用户原话>" --sem --list 5
```

跨全部博主召回，候选里每条都带 `blogger` 字段。回答时**必须逐条标清是谁说的**。

**判断不了就默认跨博主搜**，然后看候选：如果高分候选全部来自同一位博主，
就按单位博主的方式答（不用刻意强调"另一位没讲过"）；如果来自多位，就分人分条答。

## 第二步：语义召回

上面两条命令返回按相似度排序的候选摘要，`score` 是余弦分（0~1，越高越像）：

```json
{"hit": true, "scope": "all", "best_score": 0.640,
 "candidates": [{"aweme_id": "...", "score": 0.64, "blogger": "潇洒哥涂龙",
                 "summary": "...", "topics": ["彩礼"]}]}
```

`scope` 说明这次检索的范围：`blogger` 是点了名，`all` 是跨博主。

`hit=false` 直接就是拒答，**不用再判断**：

| reason | 含义 |
|---|---|
| `below_score` | 最高分没过门槛，确实没讲过 |
| `out_of_scope` | 擦边题：话题领域相关但这件事没讲过 |
| `unknown_blogger` | 用户点的名字库里没有，如实说收录了哪几位 |
| `no_embedder` | 没装 fastembed，见「首次使用」 |

`unknown_blogger` 要特别处理：**不要拿别人的观点凑给这位不存在的博主**，
直接告诉用户库里收录的是哪几位。

## 第三步：你来判断（不可跳过）

向量只衡量「语义有多近」，**不衡量「他到底讲没讲过」**。这是它的天花板：
「婆婆不给我带孩子怎么办」能拿 0.547，比最弱的命中题 0.467 还高——
因为婆媳、责任确实是他常年讲的话题，只是没讲过带孩子这件事。

候选拿回来后，逐条看 `summary`：

- 用户问的那个点在 summary 里有明确对应 → 能答
- 只是主题词相同（都提"父母""孩子"），主张讲的是另一件事 → **不能答**
- 候选里最贴切的也只是勉强沾边 → **直接说没讲过，不要进第四步**

跨博主时额外一条：**候选的相关度可能差很多**。某位博主只有 0.52 勉强沾边、
另一位 0.71 讲得很透，就只答讲得透的那位，不要为了"覆盖所有人"把勉强沾边的也写进去。

## 第四步：取原文作答

```bash
python scripts/retrieve.py --pick <aweme_id,...>
```

`--pick` 认完整 id，也认后 6 位短 id，跨博主取也能用（aweme_id 全平台唯一）。
返回的每条都带 `blogger` 字段。

### 快答：跳过第三步

候选最高分明显赢出时（`best_score ≥ 0.60` 且 `margin ≥ 0.2`），可以一步拿到原文：

```bash
python scripts/retrieve.py "<用户原话>" --sem [--blogger <名字>]
```

脚本会过滤掉不达标的候选（门槛 = `max(该博主的阈值, 最高分 × 0.6)`），
只带真正够格的一两条原文回来，不捎带无关视频。

## 查原文 / 列博主

```bash
python scripts/read.py                                  # 列出收录了哪些博主、各多少条
python scripts/read.py --list                            # 列出全部文案目录
python scripts/read.py --list --blogger 潇洒哥            # 只看这位博主的
python scripts/read.py --id <aweme_id>                   # 读某条全文
python scripts/read.py --search "关键词"                  # 找某句话出现在哪几条
python scripts/read.py --search "关键词" --blogger 潇洒哥  # 只在这位博主里找
```

用户问「你都收了谁」「能问哪些人」时跑 `python scripts/read.py --bloggers`，如实读清单。

## 作答规则

**点名一个人**（`scope=blogger`）：按结论 / 依据 / 出处三段答，出处写发布日期 + 标题 + 链接。

**跨多方**（`scope=all`）分两种情况：

- 多位博主都讲过 → **按人分条**，每条「某某说：…」+ 出处，**不要揉成"综合来看"**
- 只有一位讲过 → 直接答这一位，并说明「目前收录的内容里只有他谈过这个」

**多位博主观点的对比**，只做并列呈现，不评判谁对、不替他们调和，
也不要说"他们意见一致"除非原话确实一致。

## 硬禁止

- 不用通用常识填补文案空白。
- 不把自己的观点说成博主的观点。
- **不把 A 博主的话安到 B 博主头上** —— 这是多博主库最容易出的事故，引用前核对 `blogger` 字段。
- 不编造出处。出处缺失的条目不使用。
- 不替用户创造"几位博主的共识"，除非确有共同表述。
- 涉及心理诊断、个体治疗方案的问题，即使命中也不给具体建议，引导咨询专业人士。
- 不替博主回答范围外问题，包括"那你觉得呢""你推荐哪个"这类追问。

## 首次使用

```bash
python scripts/check.py
```

正常输出形如 `ok 2 blogger(s), 1273 summaries, 1283 transcripts, 1273 vectors, version 4`，
之后按博主逐行列出条数。

| 输出 | 处理 |
|---|---|
| `ok ...` | 就绪 |
| `broken ...` | 数据不一致，逐行的 `✗` 说明原因；不要在这种情况下作答，先修库 |
| `missing ...` | 包不完整，告知用户重装；不要编造答案 |

### 依赖

```bash
pip install numpy fastembed
```

- 向量库随包分发，**用户端不重新编码文案**，只编码问题。
- 第一次运行会把 bge-small-zh-v1.5 模型（约 95MB）下到本地缓存，之后离线可用。
- 国内直连 huggingface 会超时，先设 `HF_ENDPOINT=https://hf-mirror.com`。
- 有 OpenAI 兼容的 embedding 接口时，设 `EMBED_API_BASE` / `EMBED_API_KEY` 可走 API，
  但**模型必须跟建库时一致**，否则维度不同、直接报错。
